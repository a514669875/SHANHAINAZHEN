# 封装准备说明（综合整理）

> 本文汇总当前共识：**谁在用、怎么部署、集中存储与安全、数据与升级**，作为进入**封装阶段**的对照清单。  
> 与 [README](../README.md)、[UAT-manual-phases.md](./UAT-manual-phases.md)、`scripts/backup.py` 配合使用。

---

## 一、使用场景与目标

| 项 | 共识 |
|----|------|
| 人数与能力 | 约 **2～3 人**（含管理员），**非开发人员**日常使用 |
| 环境 | 家中开发 → **带到公司**；办公室 **一台电脑作服务端**，其他人浏览器访问 |
| 存储 | **集中式**：数据库与流程/归档文件均在 **运行 `start.bat` 的服务器本机 `backend\data`**（封装默认端口 **18080**）；同事仅浏览器访问 |
| 封装目标 | **尽量少配置**（接近解压/安装即用）、**升级路径清晰**、**优先兼容 Windows 10/11 + Chrome/Edge** |

---

## 二、部署角色

| 角色 | 做什么 | 小白操作 |
|------|--------|----------|
| **服务端** | 运行主后端（**`start.bat` 默认 18080**），并（封装后建议）**同时提供已构建的前端静态页**，局域网可访问 | 固定一台机，**双击 `scripts\start.bat`**，不要关黑窗口或按文档说明托管为服务 |
| **同事电脑** | 仅 **浏览器** 访问 `http://服务端IP:18080`（若改过 `SHANHAI_PORT` 则以实际为准） | **无需**安装 Python/Node |

### 2.1 日常只需一台机开封装端口（默认 18080）

- **标准做法**：办公室**服务器**双击 **`scripts/start.bat`**（或兼容别名 `start_production.bat`）即可；归档与流程文件写入该机的 **`backend\data`**。
---

## 三、文件与访问模型（现行）

- **数据落盘**：与采购、归档相关的生成文件与上传文件，路径相对于 **`ARCHIVED_FILE_ROOT` / `PROCUREMENT_PROCESS_ROOT`**（默认即 **`backend\data`** 下子目录），**不依赖**各同事本机磁盘。
- **权限**：项目可见性、导出、编辑等仍由 **服务端上的登录角色**（系统管理员 / 采购管理员 / 经办人）控制，与集中存储一致。

---

## 四、推荐封装形态（实施方向）

1. **发布包 = 绿色目录**（或后续再加安装包如 Inno Setup）  
   - 内含：已安装依赖的 **`backend` venv**、已构建的 **`frontend/dist`** 或 **`backend/web/dist`**、启动脚本、根目录 **`VERSION.txt`**、简明《公司使用说明》。  
   - **已实现**：`scripts\build_release.bat`（构建 + 同步 `backend\web\dist`）→ `scripts\start.bat`；说明见 **[deploy-packaged.md](./deploy-packaged.md)**。
2. **一键启动**  
   - 服务端：**`scripts\start.bat`**：`uvicorn` **监听 `0.0.0.0`，默认端口 18080**（`SHANHAI_PORT` 可改），自动挂载静态页（若 dist 存在）。
3. **生产访问**  
   - **单进程同时托管 API + 静态前端**（已实现于 `app/main.py`）；开发机仍可按 README 用 Vite。
4. **程序与数据分离**  
   - 数据库、上传/归档根路径等放在固定 **数据目录**；升级时 **覆盖程序、保留数据目录**，并先 **备份**。
5. **版本与升级**  
   - 根目录 **`VERSION.txt`**；升级说明中写明是否执行 **`scripts/migrate_add_columns.py`** 等迁移；固定流程：**停服务 → `backup.py` → 替换/迁移 → 再启动**。

---

## 五、数据迁移与「资料越来越多」

| 类型 | 常见做法 | 难度（有纪律时） |
|------|----------|------------------|
| **数据库** | 随版本提供迁移脚本；升级前备份 | **常规**，依赖脚本与说明齐全 |
| **磁盘上的项目文件夹与归档** | 多数功能升级 **不必搬文件**；仅当目录规则变更时再专项迁移 | **按需**，事先评估即可 |

**纪律**：每次大改或发版前执行 **`python scripts/backup.py`**（见 README / UAT 文档）。

## 六、封装阶段交付物建议

- [ ] **服务端发布目录**（venv + 后端代码 + `dist` + 启动脚本）
- [ ] **`VERSION.txt`** 与 **《公司使用说明》**（1～2 页：谁开机启动、网址、防火墙、忘记密码找谁、备份 `backend\database` 与 `backend\data`）
- [ ] **升级说明模板**（停服务、备份、是否运行迁移、覆盖哪些目录）
- [ ] （可选）桌面快捷方式、**`logs/`** 日志目录、内网 IP 查看说明

---

## 七、上线前快速检查（抽样）

- [ ] 服务端本机浏览器能打开系统并登录  
- [ ] **另一台电脑**仅用浏览器访问 `http://服务端IP:18080`（或当前配置的端口）成功  
- [ ] 在服务器上抽查：**上传/预览合同**路径均在 **`backend\data`** 下可读  
- [ ] **`backup.py`** 在目标环境跑通，`backups` 目录有带时间戳的备份  
- [ ] 按 [UAT-manual-phases.md](./UAT-manual-phases.md) **阶段 0 + 阶段 1** 过一遍核心路径（时间允许时）

---

## 八、暂不纳入封装「第一期」的可选项（避免范围膨胀）

- Docker（对纯小白往往更重）  
- 全仓大重构、依赖大升级（单独立项）  
- 复杂安装向导（可在绿色包稳定后再做）

---

**总结**：封装目标是把 **主服务（默认 18080）+ 静态前端** 做成 **少步骤启动**；**文件与库均集中在服务端**；**数据与程序分离 + 备份 + 版本化迁移**，保证后续加功能时迁移可控。本文作为进入封装开发的**共识基线**，实施细节可在实现启动脚本与目录结构时逐条勾选更新。
