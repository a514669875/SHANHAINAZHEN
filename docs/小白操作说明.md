# 山海纳珍录 · 小白操作说明

> 写给**不会写代码**的同事：按顺序做即可。遇到问题把**黑色窗口里的最后几行字**拍照或复制给维护的人。

---

## 一、先分清：您用的是哪种电脑？

| 您的角色 | 您要做什么 |
|----------|------------|
| **办公室里的「服务器」那台** | 每天要**启动系统**，让别人能打开网页；**合同与归档文件也在这台机的硬盘上**（`backend\data`） |
| **普通同事** | **只开浏览器**，输入网址即可使用（文件都在服务器上，无需在自己电脑再开别的程序） |

---

## 二、服务器那台电脑（最重要）

### 2.1 每天上班怎么开系统？

1. 找到项目文件夹（例如 `D:\ShanHaiNaZhen_system`）。
2. 双击打开文件夹 **`scripts`**。
3. 双击运行：**`start.bat`**（若您习惯旧名字，也可用 **`start_production.bat`**，效果相同）。  
4. 会弹出一个**黑色窗口**，**不要关**，最小化即可。  
5. 等几秒后，在本机打开浏览器（Chrome 或 Edge），地址栏输入：

   **`http://127.0.0.1:18080`**

6. 能出现**系统首页**，说明成功。

### 2.2 别的同事怎么进来？

- 他们**不用**运行黑色窗口，只要浏览器里输入：

  **`http://这台服务器的IP地址:18080`**

- **IP 怎么查？** 在服务器上：按 `Win + R`，输入 `cmd` 回车，再输入 `ipconfig` 回车，找 **IPv4 地址**（一般是 `192.168.x.x`）。

### 2.3 下班能关吗？

- 可以。关掉 **`start.bat`** 的黑色窗口，就等于**关掉系统**，别人暂时打不开。  
- 第二天再双击 **`start.bat`** 即可。

---

## 三、普通同事（日常用法）

1. 确认**服务器那台电脑**已经按第二节开好了系统。  
2. 打开 **Chrome** 或 **Edge**。  
3. 地址栏输入同事告诉您的地址，例如：`http://192.168.1.100:18080`（数字以实际为准；若维护人员改过端口，以对方告知为准）。  
4. 单机工作台模式下**无需登录**，打开即可使用。

**不需要**安装 Python、Node，也不用运行任何 `.bat`。上传的合同、归档文件都保存在**服务器**上，与您本机是否关机无关。

## 六、打包和搬运文件（您问「封装完了为啥没见安装包」——看这里）

### 6.1 先说清楚：封装 ≠ 桌面上自动多出一个「安装包」

现在仓库里的「封装」是指：**程序已经支持**「只开 **一个端口**（默认 **18080**，减少与常见 **8000** 占用冲突）就能同时打开网页 + 接口」，并配好了 **`scripts` 里的一键脚本**。  

**并不会**在您硬盘上自动生成一个叫 `山海纳珍录安装.exe` 的东西。  

**真正带到公司的「那一包」**，需要您（或维护的人）按下面步骤：**先生成网页 → 再整个文件夹拷走**。这样同事在公司电脑上看到的，就是**一整份文件夹**，和在家里开发用的是**同一套目录结构**。

---

### 6.2 在家里（或任意一台装了 Node.js 的电脑）：先把「网页文件」做出来

> 这一步**只要做一次**（或每次改版前端后再做一次）。**不会用命令行的**，可以只把本节截图给会操作的人做。

1. 把整个项目文件夹放在固定位置，例如 **`D:\ShanHaiNaZhen_system`**（路径随意，但**不要**放在需要同步很厉害的网盘根目录里，容易卡）。  
2. 在这台电脑上已安装 **Node.js**（从 nodejs 官网下载安装即可）。  
3. 打开文件夹 **`scripts`**，双击运行：**`build_release.bat`**（**一步完成**）。  
   - 作用：生成网页成品并**自动同步**到 **`backend\web\dist`**。  
   - 第一次运行可能会很久（要 `npm install`），请耐心等待，**不要关黑色窗口**。  
4. 若 **`backend\venv`** 还没有：按 **[README](../README.md)** 在 **`backend`** 里创建虚拟环境并 `pip install -r requirements.txt`（维护的人来做即可）。

做到这里，您就拥有了一份**「带网页的完整工程文件夹」**，可以进入下一节整体搬运。

---

### 6.3 用 U 盘 / 移动硬盘：要拷贝哪些东西？

**最简单、最不容易出错的做法：**

- 把整个 **`ShanHaiNaZhen_system`** 文件夹**原样复制**到 U 盘（或压缩成 **`.zip` 再拷**，到公司再解压）。

**至少**要包含这些（缺了会启动失败或没有网页）：

| 必须有的内容 | 说明 |
|--------------|------|
| **`backend` 整个文件夹** | 里面有 **`venv`**、**`app`**、**`database`**（若有库）、**`data`**（上传/归档等）、以及 **`web\dist`**（若跑过同步脚本，里面就是网页） |
| **`scripts` 文件夹** | 里面有 **`start.bat`**、**`build_release.bat`** 等 |
| **`VERSION.txt`**（在工程最外层） | 版本号，没有也不影响启动，但建议带上 |
| **`docs`**（可选但建议） | 含本 **`小白操作说明`** |

**不用拷的（可减小体积，非必须）：**

- **`frontend\node_modules`**（体积巨大；到公司若只运行封装版，可以不拷；需要在家改前端再 `build` 的电脑要保留）  
- 若确定公司机**只运行、不改代码**：可以不拷 **`frontend`** 整个文件夹，**但**必须保证 **`backend\web\dist`** 已经用 6.2 节同步过，否则浏览器打不开页面。

---

### 6.4 到公司电脑上：怎么放、第一次怎么用？

1. **把整个文件夹**从 U 盘**复制**到公司电脑硬盘，例如 **`D:\ShanHaiNaZhen_system`**（**不要**只拷 `backend` 里某几个文件，除非您很确定自己知道在做什么）。  
2. **路径可以变**，但建议**不要有空格、不要有中文路径**（减少莫名其妙报错）。  
3. **若公司电脑从来没跑过本系统**：  
   - 需要已安装 **Python 3.11+**（与 README 一致）；  
   - 若 U 盘里是**从另一台 Windows 原样拷来的 `venv`**，多数情况**可以直接用**；若双击启动报错，请维护的人在 **`backend`** 里**删掉 `venv` 重新创建**并再执行一次 `pip install -r requirements.txt`（详见 README）。  
4. **若要把家里的数据一起带来**（工程、采购、台账等）：  
   - 务必把 **`backend\database`** 里 **`shanhai.db`**（或您自定义的数据库文件）**一起拷过来**；  
   - 合同、归档文件若在服务器本机磁盘上，还要把 **`backend\data`** 以及您在系统里配置过的**归档根目录**一并一致地拷过来（或按维护的人说明映射到新盘符）。  
5. 按**第二节**双击 **`scripts\start.bat`**，浏览器访问 **`http://127.0.0.1:18080`** 试用。

---

### 6.5 搬运前多一步（强烈建议）

在**家里那台**、还在跑系统的时候，先在工程根目录执行一次备份：

```text
python scripts\backup.py
```

把生成的 **`backups`** 里最新文件夹**也拷到 U 盘**。这样即使拷贝中途 U 盘坏了，还有一次救命备份。

---

### 6.6 自己做一个「压缩包」发给公司（可选）

若您会**右键压缩文件夹**：

1. 确认已做 **6.2**（已运行 **`build_release.bat`**，`backend\web\dist` 已有网页）。  
2. 可删掉 **`frontend\node_modules`** 再压缩，体积会小很多（**不要删** **`backend\venv`** 除非公司会重装环境）。  
3. 右键 **`ShanHaiNaZhen_system` 文件夹** → **发送到** → **压缩(zipped)文件夹**，得到 **`ShanHaiNaZhen_system.zip`**。  
4. U 盘带走，到公司**解压到 D 盘某目录**，再按 **6.4** 启动。

---

### 6.7 还是没有「安装包」时，您手里应该有什么？

检查这三样是否在公司电脑上存在：

1. **`backend\venv\Scripts\python.exe`**（有，说明 Python 环境在）  
2. **`backend\web\dist\index.html`** 或 **`frontend\dist\index.html`**（有其一，说明网页已打包）  
3. **`scripts\start.bat`**（有，说明能按小白方式启动）

三项都对，就可以按第二节日常开机使用。

更偏技术的说明见：**[deploy-packaged.md](./deploy-packaged.md)**。

## 八、常见问题（先看这里）

| 现象 | 您可以先试 |
|------|------------|
| 浏览器打不开、一直转圈 | 服务器上 **`start.bat`** 的黑窗口是否还开着？先重开一次。 |
| 别人能开，我开不了 | 地址是否写对？是否和服务器在**同一 Wi‑Fi / 同一办公室网络**？ |
| 预览合同提示文件不存在 | 文件应在**服务器**的 **`backend\data`**；请维护的人检查是否误删或未随库一起备份还原。 |
| 黑窗口一闪就没了 | 可能环境没装好，把文件夹给维护的人检查，或看 **[deploy-packaged.md](./deploy-packaged.md)**。 |
| 黑窗口提示 **Address already in use** / 端口被占用 | 先关旧的黑窗口，或运行 **`scripts\stop.bat`**（与 `start.bat` 同默认端口 **18080**）。仍冲突时，在启动前执行 `set SHANHAI_PORT=其他未占用端口` 再开 `start.bat`，浏览器地址中的端口要一起改。 |
| 黑窗口里一堆乱码、`ho` 不是命令、`--port` 不是命令 | 多为 **批处理编码** 问题：请更新到最新仓库里的 **`scripts\*.bat`**（已改为英文提示、避免 UTF-8 中文在 cmd 下乱解析）。 |
| 打开只有一行 JSON、没有网页 | 说明**网页没打包**或**没拷全**：回到 **第六节**运行 **`build_release.bat`**。 |
| U 盘拷过去启动报错 | 路径是否含中文/空格；**`venv` 是否完整**；必要时在公司机按 README **重建 venv**。 |

## 九、和「开发」方式的区别（不用记，看一眼即可）

- **开发**：要开两个东西（后端 + 前端 5173），适合改程序的人。  
- **您现在用的封装方式**：服务器上**只开** **`start.bat`**，浏览器用 **默认 18080** 这一个端口即可（维护人员可用环境变量改成别的端口）。

更完整的安装与升级步骤见：**[deploy-packaged.md](./deploy-packaged.md)**。
