## 二、发现的问题（不修改代码，仅记录）

### 1. 测试脚本解析问题
- **五选二供应商数量**：解析到 25 家供应商，期望 5 家。疑为流程时间表中含「供应商」的行被误解析。
- **测试项目3 直接采购**：解析到 11 家供应商，期望 1 家。疑为流程时间表（如「供应商推荐表」）被误解析为供应商表。

### 2. 补充协议主合同依赖
- **现象**：补充协议需选择主合同，主合同须已在台账中。
- **说明**：台账在归档（上传合同文件并勾选合同）时生成，新建采购项目不会自动生成台账。
- **影响**：无法通过脚本直接创建补充协议，需先对主合同做归档操作。

### 3. 含税报价 ≤ 控制价校验
- 测试数据中五选二供应商报价均 ≤ 控制价，未触发该校验。
- 补充协议 1.9 控制价为「/」，按规则应跳过校验；新增金额为负数（-1026753.84），系统是否支持负金额未验证。

### 4. 供应商数量约束
- 邀请询比、单一来源、直接采购、五选二的数量约束在 API 层已生效。
- 因脚本解析问题，部分采购方式未能正确传入供应商列表。

## 三、建议后续验证

1. **人工前端操作**：在浏览器中按测试数据逐项录入，重点验证：
   - 补充协议创建流程（含主合同归档后再选主合同）
   - 台账、采购清单、工程项目清单的字段同步
   - 流程文件夹及 目录.docx 的生成

2. **文件夹与文件**：检查 `PROCUREMENT_PROCESS_ROOT` 下是否按规则生成：
   - 工程编号+工程名
   - 工程编号-采购内容（或 工程编号-采购内容-标段名）
   - 目录.docx 及流程 Word 文件

3. **台账同步**：归档后检查智能台账中合同编号、供应商、合同价、签订日期、控制价等是否正确。

## 四、测试脚本说明

脚本路径：`scripts/run_test_data.py`  
运行前需启动后端：`cd backend && uvicorn app.main:app --host 0.0.0.0 --port 8000`  
运行：`backend\venv\Scripts\python.exe scripts\run_test_data.py`

脚本会尝试创建已存在项目时复用，采购项目会持续追加，多次运行会产生重复数据。
