# 山海纳珍录——工程项目采购管理系统
## UI设计文档（最终版 ）

## 一、设计原则

### 1.1 用户体验原则
- **简洁直观**：界面布局清晰，功能入口明确，减少用户学习成本
- **操作高效**：常用功能快捷可达，支持批量操作，提升工作效率
- **信息完整**：关键信息完整展示，支持横向滚动查看全部字段
- **交互一致**：全系统统一交互规范，双击进入详情、右上角搜索、底部分页

### 1.2 视觉设计原则
- **层次分明**：通过字体大小、颜色深浅区分信息层级
- **重点突出**：关键操作按钮高亮显示，重要数据醒目呈现
- **风格统一**：全系统保持统一的色彩、字体、图标风格

### 1.3 功能设计原则
- **流程完整**：从工程立项→采购→归档→台账，全流程闭环管理
- **数据准确**：关键字段必填，数据校验，避免错误录入
- **追溯可查**：操作路径清晰，文件关联完整，便于审计追溯

### 8.4 数据格式与交互规范（2026-03）

| 项目 | 规范 |
|------|------|
| **日期格式** | 统一 Y.M.D（如 2026.3.13）；所有日期展示、输入 placeholder 均采用此格式 |
| **数值框** | 支持负数；允许输入「/」，存储为 null、显示为「/」；适用于所有数值输入框 |
| **编辑第一步只读** | 采购类型、采购方式只读；补充协议下的主合同、标段等也一并只读 |
| **补充协议主合同** | 编辑时第一步须正确显示已选主合同 |
| **五选二供应商** | 编辑时须显示全部5家供应商，便于修改 |
| **控制价 "/"** | 用户输入「/」时存储为 null，台账及清单显示「/」 |
| **补充协议控制价** | 台账及清单中补充协议「控制价」用 supplement_control_price，非新增金额 |
| **补充协议签订日期** | 若早于主合同签订日期，弹出提示确认；同一主合同下补1早于补2早于补3…，若违反则弹框提示 |
